**Title:** `fix(hotkey): keep a refused tap from swallowing the next one`

```markdown
## Summary
In Single Tap and Double Tap modes, a tap the session turns down (model preparing, permission missing, previous dictation still transcribing) no longer swallows the user's next tap. The tap machine stops tracking "recording" itself and reads it from `RiverSession` on each tap.

## Scope
- `TapStateMachine`, `HotkeyManager`, `RiverSession`
- Tests: `TapStateMachineTests`, `HotkeyManagerTests`, `RiverSessionTests`
- `docs/architecture/river-pipeline.md`, `CHANGELOG.md`

## Changes Made
- `TapStateMachine`: drop the `.recording` state and `reset()`; `handleTap(isRecording:)` takes the session's state and keeps only the double-tap timing.
- `HotkeyManager`: add an `isRecording` provider read on each completed tap; remove `resetTapState()`.
- `RiverSession`: wire `hotkey.isRecording` to `currentState == .recording`; drop the cancel-time tap reset, which is no longer needed.
- Update tests for the new contract and add session coverage; note the change in the architecture doc and CHANGELOG.

## Impact
- Fixes the bug where a refused start left the tap machine believing a recording was live, so the next tap was read as a stop and did nothing.
- Removes a second copy of the recording state, so the cancel path no longer needs a manual reset.
- Hold mode is unaffected.
```

**Title:** `fix(hotkey): read recording state from the session on each tap`

```markdown
## Summary

In Single Tap and Double Tap modes, a tap that River refused to act on swallowed the next one. Tapping while the model was preparing, a permission was missing, or the last dictation was still transcribing left the tap machine believing a recording had started, so the following tap read as a stop and did nothing. `TapStateMachine` now keeps only the double-tap timing and reads whether a recording is live from `RiverSession` on every tap.

## Changes

- `TapStateMachine`: remove the `.recording` state and `reset()`; `handleTap(isRecording:)` takes the session's state and returns `.stop` when it is recording.
- `HotkeyManager`: add an `isRecording` closure, pass it to `handleTap`, and remove `resetTapState()`.
- `RiverSession`: set `hotkey.isRecording` from `currentState == .recording` and drop the `resetTapState()` call in the cancel path, which the new design makes unnecessary.
- `TapStateMachineTests`, `HotkeyManagerTests`, `RiverSessionTests`: rewrite for the new signature and add cases for a refused start followed by another tap.
- `docs/architecture/river-pipeline.md`, `CHANGELOG.md`: describe the new ownership and add a Fixed entry.

## Impact

Changing the activation mode mid-recording now clears the double-tap window and nothing else; the next tap still stops the recording because the session reports it.
```
