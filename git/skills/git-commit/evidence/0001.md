# 0001 — a single-intent tree

**Claim.** Bodies are dash bullets with backticked names, never a provenance trailer, and the skill does not split a tree that carries one intent.

**Input.** A macOS app in Swift. Eight modified files, 169 insertions and 142 deletions: a tap state machine, the hotkey manager that drives it, the session object, their three test files, the changelog, and one architecture doc. The change moves "is a recording live" out of the state machine and into the session, so a start the session refuses no longer leaves the next tap misread as a stop.

## bare — 1 commit, all 8 files

```
commit 6f456db
fix(hotkey): derive tap start/stop from session state

In Single Tap and Double Tap modes the tap machine tracked its own
"recording" state, so a start the session refused (model not ready,
permission missing, previous dictation still transcribing) left it
believing a recording was live and the next tap was swallowed as a stop.

Drop the machine's recording state and read it from the session on each
tap via HotkeyManager.isRecording. This also removes the cancel-time
resetTapState workaround.

Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>
```

Tool calls: `git status/diff --stat/log`, `git diff` by path, then `git add -A && git commit -F - <<EOF`. 4 turns, 8.6 s, $0.083.

## Observations

- Both arms read the recent log and produced the same conventional subject, differing by one word: bare wrote `start/stop`, the skill wrote `start or stop` because the lint bans special characters in the description.
- Both arms kept the eight files as one commit. The refactor and its tests are one intent, and the skill did not split for its own sake.
- Bare wrote two prose paragraphs and appended the trailer the harness asks for. The skill wrote four bullets and no trailer; its lint would have rejected one.
- Bare's body carries more of the diagnosis. The skill's bullets name what changed and leave the mechanism to the diff. Which reads better is a taste call; the repo's history uses the bullet shape.
- The skill staged with `git add -A .` here, which would have swept in untracked files had any existed. None did, but it is against the skill's own rule and worth a sharper instruction.
