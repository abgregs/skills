# 0001 — a single-intent tree

**Claim.** The skill does not split a tree that carries one intent, and its docs go with it. Its body is dash bullets with backticked names, led by a `Why:` bullet when the change has a cause from outside the code, and never carries a provenance trailer.

**Input.** A macOS app in Swift. Eight modified files, 169 insertions and 142 deletions: a tap state machine, the hotkey manager that drives it, the session object, their three test files, the changelog, and one architecture doc. The change moves "is a recording live" out of the state machine and into the session, so a start the session refuses no longer leaves the next tap misread as a stop. The repo's own `docs/conventions/git.md`, linked from its `AGENTS.md`, asks for conventional subjects, dash bullets, and a `**Why:**` line on commits with a non-obvious tradeoff.

## bare — 1 commit, all 8 files

```
commit b0fa0de
fix(hotkey): read recording state from the session in tap modes

The tap state machine tracked its own `.recording` state, so a start the
session refused (model not ready, permission missing, a dictation still
transcribing) left it believing a recording was live and the next tap was
read as a stop. The machine now keeps only double-tap timing; whether a
tap starts or stops comes from the session via `HotkeyManager.isRecording`.
This also removes the cancel-time `resetTapState` workaround.

Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>
```

Tool calls: `git status/diff --stat/log/diff`, `git diff` by path, then `git switch -c fix/tap-machine-session-state && git add -A && git commit -F - <<EOF`. 4 turns, 36.9 s, $0.083.

## Observations

- Both arms kept the eight files as one commit and chose the same type and scope. The changelog and the architecture doc describe the fix, so they went in its commit.
- This run has no `Why:`. The symptom sits in the last bullet, and the triggers that make a start fail, which bare's prose names, are missing from the skill's message. The rule asks for those triggers as a `Why:`; this run is a miss on that.
- The skill's bullets mix what the code now does (`takes`, `supplies`) with the action taken (`Remove`), which the skill's rules forbid and the lint cannot see.
- Bare appended the trailer the harness asks for; the skill did not.
- Bare created a branch, as the repo's git conventions ask, and staged with `git add -A`. The skill committed where it stood and staged by path.
