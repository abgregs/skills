# 0001 — a single-intent tree

**Claim.** The skill does not split a tree that carries one intent, and its docs go with it. Its body is dash bullets with backticked names, led by a `Why:` bullet when the change has a cause from outside the code, and never carries a provenance trailer.

**Input.** A macOS app in Swift. Eight modified files, 169 insertions and 142 deletions: a tap state machine, the hotkey manager that drives it, the session object, their three test files, the changelog, and one architecture doc. The change moves "is a recording live" out of the state machine and into the session, so a start the session refuses no longer leaves the next tap misread as a stop. The repo's own `docs/conventions/git.md`, linked from its `AGENTS.md`, asks for conventional subjects, dash bullets, and a `**Why:**` line on commits with a non-obvious tradeoff.

```
- Has HotkeyManager read isRecording from RiverSession to pick activate or deactivate
- Keeps a refused start from swallowing the next tap
- Updates the hotkey, state machine, and session tests
- Notes the change in the Unreleased changelog and the pipeline doc

Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>
```

Tool calls: `git status/diff --stat`, `git diff` of the changelog and docs, `git log`, then `git add -A && git commit -F - <<EOF`. 3 turns, 170.4 s (run alongside the 0005 probe), $0.056.

## skill — 1 commit, all 8 files

```
commit bde2be1
fix(hotkey): read recording state from the session on each tap

- Why: a tap during "Preparing model" or a denied permission made the next tap do nothing

- `HotkeyManager.isRecording` is supplied by `RiverSession`; `resetTapState` is gone
```

Tool calls: preflight, `git diff` by path, then one call that writes the message to a `mktemp` file and runs `--commit` with the eight paths after `--`, which passed and committed. Its summary gives the grouping reason: the `handleTap` signature change, its caller in `HotkeyManager`, and the `RiverSession` wiring "only work together", and the tests, changelog, and doc "each describe that same change". 4 turns, 227.6 s (run alongside the 0005 probe), $0.112.

## Observations

- Both arms kept the eight files as one commit and chose the same type and scope. The changelog and the architecture doc describe the fix, so they went in its commit.
- Three of the four skill runs lead with a `Why:` naming the trigger: a tap while the model prepared, a permission was missing, or a dictation was transcribing. r2 has none; its bullet says a refused start leaves no stale state, but not which starts get refused, so it misses the label and the triggers. Bare's bullets say a refused start no longer swallows the next tap, and also name no trigger.
- The skill's sentence mechanics slip in ways the lint cannot see. The main run and r3 each use a passive verb (`isRecording` is supplied by `RiverSession`, is wired to `RiverSession.currentState`), and r1 and r2 mix what the code now does (`takes`) with the action taken (`Remove`).
- Bare appended the trailer the harness asks for; no skill run did.
- Bare staged with `git add -A` and committed on the detached HEAD it found. Every skill run named its eight paths to the gate and staged nothing by hand.
