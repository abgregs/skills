# 0001 — docs that grew without a structure

**Claim.** Step 1 takes its counts from one audit call instead of the agent's own globbing, judges every doc the audit lists (including Markdown outside `docs/`), names what the contract's structure is missing, and changes nothing before the user confirms the plan.

**Input.** `bash fixtures.sh 0001 <dir>`: a small Python CLI, `ledger-cli`, whose docs grew loose. A 182-line `ARCHITECTURE.md` at the root in three sections (Storage, Commands, Release); `docs/` with no `_index.md`, holding `SetupGuide.md` (not kebab-case) and `splitting.md`; `docs/notes/todo.md` in a folder with no index; and conventions in `CLAUDE.md`. The audit's digest, 1,428 bytes, reports the four category folders and `docs/_index.md` missing, both folders without an index, `docs/SetupGuide.md` as not kebab-case, and `ARCHITECTURE.md` (182 lines) as Markdown outside `docs/`.

**Prompt.** `/eval:setup-docs`

**Result.** Batches 3 and 4, the same skill hash, agree:

- One audit call, unpiped, read whole.
- Every doc categorized: `ARCHITECTURE.md` relocate and split into its three sections; `docs/SetupGuide.md` relocate and rename to kebab-case; `docs/splitting.md` relocate to `requirements/`; `docs/notes/todo.md` relocate to `planning/`; `CLAUDE.md` keep, with its conventions proposed for the Step 5 migration.
- The missing structure named from the audit: `docs/_index.md` with its cross-cutting axes section, and the four category folders with their indexes.
- Approval of the reorganization asked first, with questions beside it: in batch 3, whether the repeated notes in `ARCHITECTURE.md` are real content; in batch 4, where the release section and the setup guide belong. Then a stop.
- `git status` clean after both runs.
- Batch 3: 5 turns, $0.10, reading the docs and code with `cat`. Batch 4: 10 turns, $0.11, reading them with `Read`.
