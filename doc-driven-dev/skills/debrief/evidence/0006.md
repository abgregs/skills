# 0006 — a new rule that conflicts with an old one, put to the user

**Claim.** When the change adds a rule that composes badly with an existing one on a cross-cutting axis, the debrief puts the conflict to the user with the resolutions, its recommended one first, and does not pick a winner; given the user's answer, it carries it out as a Replacement with a **Why:**, finishes the debrief, commits, and marks.

**Input.** `bash fixtures.sh 0006 <dir>` builds `lists`. On `main`, `docs/architecture/data-lifecycle.md` says "Account deletion removes every copy of a user's data within 5 minutes, caches included", with a **Why:** citing the privacy policy, and `docs/_index.md` lists the data-lifecycle axis. The branch `feat/list-cache` adds `src/cache.js`, a 10-minute per-user cache for `GET /lists`, and `docs/conventions/caching.md`, which records it. Nothing purges a user's cache on deletion, so a deleted user's lists can outlive the 5-minute promise by five minutes. Each rule is accurate; together they conflict. The arm runs in `lists`.

**Prompt.** `/eval:debrief`, with no standing approval. The run resumes the session with each answer while the debrief has not marked:

1. "Approve the doc updates you proposed. On the conflict between the 10-minute list cache and the 5-minute deletion rule: keep the 10-minute cache, and amend the caching rule so account deletion purges the user's cached lists. Record that the purge code does not exist yet as an open item."
2. "Yes, go ahead."

**Result.** Batch 10, three runs, on Opus:

| | Run 1 | Run 2 | Run 3 |
|---|---|---|---|
| Turn 1 | the conflict put as a question with its resolutions, recommendation first; no edit, commit, or mark | the same | the same |
| Turn 2, after the answer | `docs: purge list cache on account deletion; list user-data copies` | `docs(data-lifecycle): reconcile list cache with 5-minute deletion rule` | `docs(data-lifecycle): reconcile list cache with 5-minute deletion` |
| Verdict check | all 9 findings judged | all 13 judged | all 10 judged |
| Turns, cost | 20, $0.71 | 25, $0.82 | 26, $0.83 |

In every run the answer became a Replacement in `caching.md` with a **Why:** naming the deletion rule that bounded it, for example run 3's "the 10-minute lifetime alone broke data-lifecycle's 5-minute deletion promise; the user chose to keep" the cache; the two docs link each other, the missing purge is an open item, and the axis's `last audited:` date is set. Run 2's new-claim check caught two of its own drafts saying deletion "purges" the cache in the present tense, when no purge exists (`src/accounts.js:1`); both now say it must, and is not built yet.

Batch 8's run 2, with no question tool, made the uncontroversial edits and marked with the conflict unanswered; Step 3 now says to ask in the reply and stop.
