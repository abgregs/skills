# 0008 — the debrief that follows the work, in the same session

**Claim.** A debrief run in the session that did the work reads each doc from disk rather than from what the session remembers writing, greps the docs for the terms the session's own decisions retired, which no diff can show, takes a **Why:** from a reason the user gave in chat, and leaves no stale or wrong statement for a "be extra sure" follow-up to find. An open item the follow-up adds, such as work the code has not done yet, is not a miss.

**Input.** `bash fixtures.sh 0008 <dir>` builds 0004's repo: `ledger` storing money as float dollars in `amount_dollars`, `docs/conventions/money.md` and `docs/architecture/entries.md` saying so, and `feat/cents` checked out with no commits. The arm runs in `ledger`, and the session does the work itself.

**Prompt.** Four turns of one session, each resuming the last:

1. "Switch money amounts from float dollars to integer cents: store `amount_cents` in the entries table, and convert with a `toCents` helper in `src/currency.js`. Commit the code when it is done."
2. "Actually, call the column `amount_minor`, not `amount_cents`: we will add currencies without cents, such as yen. Update the code and commit it."
3. "/eval:debrief The user is away for this run: treat every doc update you recommend as approved, and take your recommended option wherever you would ask a question."
4. "Double-check for stale items and cross-cutting concerns, just to be extra sure."

`amount_cents` was never on `main`, so it is on no removed line: if a doc took it up in turn 1 and kept it, the sweep cannot raise it, and only Step 5's session-decision check can. The reason for `amount_minor` exists only in turn 2.

**Result.** Batch 10, three runs, on Opus:

| | Run 1 | Run 2 | Run 3 |
|---|---|---|---|
| Turn 3, the debrief | greps the docs for `amount_cents`; commit, then mark | the same | the same |
| `amount_minor` **Why:** | the yen reason, from turn 2 | the same | the same |
| Turn 4 finds | no false statement; an entry records no currency, raised and left unrecorded | `entries.md`'s "an integer in the currency's minor unit" reworded to say entries carry no currency; `money.md` already said so | no false statement; the same missing currency column added as an open item |
| Under the bar | pass | pass | pass |
| Turns, cost, all four turns | 36, $2.32 | 41, $2.39 | 35, $2.46 |

The bar is graded by the literal rule: a miss is a statement the code contradicts. Every turn-4 item is the one gap, that entries have no currency column, which `money.md` recorded in turn 3 only in run 2. "The currency's minor unit (cents for USD)" is true while every amount is USD, so the gap is an open item. Batch 8 called that sentence wrong; under this rule its runs found an open item too, and batch 9's run 2, whose follow-up corrected "rounds to the nearest cent", which `1.005` contradicts, is the one recorded miss.

The agent chose its own course in turns 1 and 2: in batch 8 it ran a debrief after each coding turn, as the fixture's `CLAUDE.md` asks, and in batches 9 and 10 it ran `--scope` and left the debrief to turn 3.
