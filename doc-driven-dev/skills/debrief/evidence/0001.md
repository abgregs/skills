# 0001 — a branch in a fresh worktree

**Claim.** A branch checked out in a fresh worktree, with no mark of its own, is compared from its branch point rather than its last five commits. The author's own **Why:** line, which names the old header, does not hide the stale convention from the sweep. The convention is fixed as a replacement with a **Why:**, every finding the debrief's sweeps raised is judged before it ends, and the mark lands in the common git directory, where every worktree of the repo reads it, with nothing written under `.claude/`.

**Input.** `bash fixtures.sh 0001 <dir>` builds `shelf` on `main` and a worktree `shelf-tokens` on `feat/access-tokens`, eight commits ahead: seven migration steps, then the change that replaces session tokens with bearer access tokens in `src/auth.js` and rewrites `docs/architecture/auth.md`. The rewrite records the replacement as the docs contract asks, in a line that names the old header: "**Why:** replaces the 30-day server-side session token sent in `X-Session`: a leaked session token stayed valid for a month." Two docs are left as the branch found them:

`docs/conventions/api-endpoints.md:4`

```
- Every route but `/login` requires the session token in the `X-Session` header.
```

and two standing faults the change does not touch: `docs/planning/` with a doc and no `_index.md`, and a generated `docs/reference/schema.md` of 171 lines. No mark exists. The arm runs in `shelf-tokens`.

**Prompt.** `/eval:debrief The user is away for this run: treat every doc update you recommend as approved, and take your recommended option wherever you would ask a question.` A real debrief follows the work with a bare `/debrief`, so the prompt names no change.

**Result.** Batch 10, three runs, on Opus:

| | Run 1 | Run 2 | Run 3 |
|---|---|---|---|
| `--scope` base | the merge-base with `main` | the same | the same |
| Sweeps: retired, referrer, structure, new claims | 0, 2, 0, 3; then 0, 2, 0, 7 | 2, 1, 0, 2; then 0, 2, 0, 5 | 2, 1, 0, 2; then 0, 2, 0, 5 |
| Verdict check | all 9 findings of this debrief judged | the same | the same |
| Detector calls piped | none | none | none |
| Commit, then `--mark` | `docs(auth): align endpoint convention with bearer access tokens` | the same subject | the same subject |
| Mark | `shelf/.git/doc-sweep-mark`, at the commit | the same | the same |
| Turns, cost | 23, $0.46 | 24, $0.49 | 21, $0.42 |

The author's **Why:** line in `auth.md` names `X-Session`, and in runs 2 and 3 the first sweep still raised it as a retired term; run 1 fixed `api-endpoints.md:4` before its first sweep. Every run rewrote that line to the `Authorization: Bearer` header with a **Why:** reusing the author's reason, "a leaked session token stayed valid for a month", the only reason any file states. After each run `X-Session` appears in `docs/` only inside **Why:** lines; nothing under `.claude/`.

Run 1's new-claim check caught a claim the code does not bear out: `auth.md` said the token is verified, but `verifyAccessToken` at `src/auth.js:8` checks neither signature nor expiry. The run said so in `auth.md` and opened a planning doc for it.
