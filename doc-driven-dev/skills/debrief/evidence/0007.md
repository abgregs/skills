# 0007 — no reliable base, with a user to ask

**Claim.** With no mark, no commits past the branch point, and a clean tree, the agent asks the user which range to review, offering the recent commits, and then debriefs the range the user names, rather than stopping or choosing one itself.

**Input.** `bash fixtures.sh 0007 <dir>` builds 0004's repo: `ledger` with one commit storing money as float dollars, six release-note commits, and `feat/cents` checked out with no commits and nothing uncommitted. The arm runs in `ledger`.

**Prompt.** `/eval:debrief`, with no standing approval. The run resumes the session with each answer while the debrief has not marked:

1. "Review from the commit 'ledger: entries in dollars' onward."
2. "Yes, go ahead."

**Result.** Batch 10, three runs, on Opus:

| | Run 1 | Run 2 | Run 3 |
|---|---|---|---|
| Turn 1 | exit 4; asks for the range, listing the commits | the same | the same |
| Turn 2 | `--scope --base` the named commit's parent; proposes edits and asks to confirm | `--scope --base` the named commit's parent; edits, commits, marks | the same as run 2 |
| Turn 3 | "Yes, go ahead": commit, then mark | not needed | not needed |
| Doc commit | `docs: record money float rationale gap, audit money axis` | `docs: record money axis audit` | `docs: record money axis audit date` |
| Turns, cost | 17, $0.89 | 19, $0.53 | 20, $0.52 |

Every run resolved "the commit 'ledger: entries in dollars'" to its revision and debriefed from it. The range's docs already matched its code, so the sweeps raised one finding at most, and the debriefs ended on the axis date; run 1 also recorded that no doc gives the reason for storing floats.
