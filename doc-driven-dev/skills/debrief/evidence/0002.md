# 0002 — a range the user names

**Claim.** When the user names the range to review, the agent passes its start as `--base`, so the sweep reads that range and not the one since the last mark; a finding from before the range stays out of the debrief.

**Input.** `bash fixtures.sh 0002 <dir>` builds `notes` on `main` with five commits:

```
<c5> feat(notes): purge trashed notes after 30 days
<c4> docs(storage): trash replaces archive
<c3> feat(notes): replace archive with trash
<c2> (tag: v1.2) feat(folders): rename the workspace table to folders
<c1> notes: storage and states
```

`.git/doc-sweep-mark` holds `<c1>`, left by an earlier debrief. v1.2 renamed `workspace` in `storage.md`; since v1.2, archive became trash in `storage.md`, while `docs/requirements/note-states.md` still says notes "can be archived" and "Archived notes stay searchable". Without `--base`, the mark at `<c1>` would make v1.2's `workspace` rename a finding as well; with `--base v1.2` the sweep finds only `archived` (two hits) and one referrer, which the fixture's dry run confirmed. The arm runs in `notes`.

**Prompt.** `/eval:debrief Review everything since the v1.2 tag. The user is away for this run: treat every doc update you recommend as approved, and take your recommended option wherever you would ask a question.`

**Result.** Batches 3 and 4, the same skill hash, agree:

| | Batch 3 | Batch 4 |
|---|---|---|
| `--scope` call | `--scope --base v1.2` | `--scope --base v1.2` |
| Base printed | `<c2>  (--base v1.2)` | `<c2>  (--base v1.2)` |
| First sweep | `T-5a21` (`archived`, 2 hits), `R-d119` (the conventions index naming `storage.md`) | the same two |
| Re-sweep after the fixes | no findings | no findings |
| Detector calls piped | 1 | 0 |
| `--verdicts -` | `the last sweep has no findings; nothing to judge (exit 0)` | the same |
| Commit | `docs: align note states and storage with trash`, 5 docs | `docs: note states and storage describe trash, not archive`, 5 docs |
| `--mark` | `.git/doc-sweep-mark` moved to the commit | the same |
| Turns, cost | 9, $0.14 | 14, $0.15 |

Both rewrite `note-states.md` from archive to trash with a **Why:** that trash replaced archive and `archived_at` should not return, update both index summaries, and set the data-lifecycle axis's `last audited:` date. After each run `archive` appears in `docs/` only inside **Why:** lines and an open question both arms left in `note-states.md` for the product decision they could not make: whether trashed notes stay searchable, as archived notes did. Both also moved `note-states.md`'s "workspace" to "folder" while rewriting the line: not a sweep finding here, since v1.2 is outside the range, but the same line.
