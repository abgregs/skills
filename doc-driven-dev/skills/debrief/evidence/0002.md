# 0002 — a range the user names

**Claim.** When the user names the range to review, the agent passes its start as `--base`, so the sweep reads that range and not the one since the last mark; a finding from before the range stays out of the debrief, and the doc commit leaves out unrelated work in progress.

**Input.** `bash fixtures.sh 0002 <dir>` builds `notes` on `main` with five commits:

```
<c5> feat(notes): purge trashed notes after 30 days
<c4> docs(storage): trash replaces archive
<c3> feat(notes): replace archive with trash
<c2> (tag: v1.2) feat(folders): rename the workspace table to folders
<c1> notes: storage and states
```

`.git/doc-sweep-mark` holds `<c1>`, left by an earlier debrief. v1.2 renamed `workspace` in `storage.md`; since v1.2, archive became trash in `storage.md`, while `docs/requirements/note-states.md` still says notes "can be archived" and "Archived notes stay searchable". Without `--base`, the mark at `<c1>` would make v1.2's `workspace` rename a finding as well; with `--base v1.2` the sweep finds only `archived` (two hits) and one referrer, which the fixture's dry run confirmed. The tree also holds unrelated work in progress: an unstaged edit to `src/search.js` and an untracked `scratch.md`. The code the doc fixes describe is committed, so Step 6 commits the fixes, and the commit must hold only the docs. The arm runs in `notes`.

**Prompt.** `/eval:debrief Review everything since the v1.2 tag. The user is away for this run: treat every doc update you recommend as approved, and take your recommended option wherever you would ask a question.`

**Result.** Batch 7, two runs, on the earlier fixture, whose tree was clean apart from the docs. Both committed with `git add -A`, which in this fixture would also commit `src/search.js` and `scratch.md`; Step 6 now says to stage only the doc paths the debrief edited. The next batch reruns this case as written above.

| | Run 1 | Run 2 |
|---|---|---|
| `--scope` call | `--scope --base v1.2` | `--scope --base v1.2` |
| Base printed | `<c2>  (--base v1.2)` | `<c2>  (--base v1.2)` |
| First sweep | `T-5a21` (`archived`, 2 hits), `R-d119` (the conventions index naming `storage.md`) | the same two |
| Re-sweep after the fixes | no findings | no findings |
| Detector calls piped | the re-sweep, through `sed -n 1,30p`; it held no findings | none ran; one was refused by the harness |
| `--verdicts -` | `nothing to judge (exit 0)` | `nothing to judge (exit 0)` |
| Commit, then `--mark` | `docs: align note states and storage with trash`, 5 docs | `docs: trash replaces archive in note states; audit data lifecycle axis`, 5 docs |
| Turns, cost | 10, $0.15 | 9, $0.14 |

Both commits rewrite `note-states.md` from archive to trash and the 30-day purge, add a **Why:** to it and to `storage.md`, update the two index summaries, and set the data-lifecycle axis's `last audited:` date. Every **Why:** reads `reason not recorded`, since no commit, comment, or doc says why trash replaced archive. Both runs dropped "Archived notes stay searchable" and left whether trashed notes stay searchable as an open line in `note-states.md`. After each run `archive` appears in `docs/` only in those **Why:** lines and that open line. Both moved `note-states.md`'s "workspace" to "folder" while rewriting the line: not a sweep finding, since v1.2 is outside the range.

Batch 5 wrote a **Why:** with a cause no file states, "archived notes had no expiry and piled up"; the contract now says where a **Why:**'s reason comes from, and neither run of batch 6 or 7 supplied one.
