# 0002 — a range the user names

**Claim.** When the user names the range to review, the agent passes its start as `--base`, so the sweep reads that range and not the one since the last mark; a finding from before the range stays out of the debrief, and the doc commit leaves out unrelated work in progress.

**Input.** `bash fixtures.sh 0002 <dir>` builds `notes` on `main` with five commits:

```
<c5> feat(notes): purge trashed notes after 30 days
<c4> docs(storage): trash replaces archive
<c3> feat(notes): replace archive with trash
<c2> (tag: v1.2) feat(folders): rename the workspace table to folders
<c1> notes: storage and states
```

`.git/doc-sweep-mark` holds `<c1>`, left by an earlier debrief. v1.2 renamed `workspace` in `storage.md`; since v1.2, archive became trash in `storage.md`, while `docs/requirements/note-states.md` still says notes "can be archived" and "Archived notes stay searchable". Without `--base`, the mark at `<c1>` would make v1.2's `workspace` rename a finding as well; with `--base v1.2` the sweep finds only `archived` (two hits) and one referrer, which the fixture's dry run confirmed. The tree also holds unrelated work in progress: an unstaged edit to `src/search.js` and an untracked `scratch.md`. The code the doc fixes describe is committed, so Step 6 commits the fixes, and the commit must hold only the docs. The arm runs in `notes`.

**Prompt.** `/eval:debrief Review everything since the v1.2 tag. The user is away for this run: treat every doc update you recommend as approved, and take your recommended option wherever you would ask a question.`

**Result.** Batch 10, three runs, on Opus:

| | Run 1 | Run 2 | Run 3 |
|---|---|---|---|
| `--scope` call | `--scope --base v1.2` | the same | the same |
| Verdict check | all 8 findings judged | all 9 judged | all 10 judged |
| Detector calls piped | none | none | none |
| Doc commit | `docs(notes): align note states with trash and 30-day purge` | `docs(notes): trash, folders, and planned purge in note states` | `docs: align note states with trash and folders` |
| Left uncommitted | `src/search.js`, `scratch.md` | the same | the same |
| Turns, cost | 18, $0.40 | 20, $0.47 | 11, $0.35 |

Every run staged only the docs it edited, so the unrelated work in progress stayed out of the commit, then marked. Every **Why:** in `note-states.md` reads `reason not recorded`, run 2 and 3 naming the commits they read. Run 2's new-claim check caught its own draft saying trashed notes "are purged after 30 days" as if that happens, when no purge code exists (`src/notes.js:2` is a comment); the doc now calls the purge planned.

Batch 7 ran this case on a clean tree, where `git add -A` was harmless; Step 6 now stages only the doc paths the debrief edited.
